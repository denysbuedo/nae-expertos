📋 Introducción

Este documento presenta el Modelo de Desarrollo de Software con Agentes AI, un framework completo diseñado para equipos pequeños de 3-5 personas que trabajan en proyectos de Web Apps, APIs/Backend y Data/Analytics.

¿Qué es este Modelo?

Es un sistema híbrido que combina developers humanos con agentes de Inteligencia Artificial para maximizar la productividad manteniendo la calidad del código y la seguridad.

Características Principales

  • 8 agentes AI especializados: 4 de desarrollo + 4 de soporte
  • Stack estandarizado: React/Next.js, Node.js, Python, PostgreSQL
  • Templates listos para usar: Web App, API Backend, Data Analytics
  • Protocolos de testing: Cobertura 80%+, pirámide 70/20/10
  • CI/CD automatizado: GitHub Actions, Docker, deploy en 3 environments
  • Reglas de escalamiento claras: Cuándo el agente trabaja solo vs. cuándo necesita supervisión

Tipos de Proyectos Soportados

🌐 Web Apps

Aplicaciones web full-stack con Next.js, React, TypeScript y TailwindCSS

⚙️ APIs/Backend

Servicios RESTful, microservicios con Node.js/Express y Python/FastAPI

📊 Data/Analytics

Pipelines ETL, análisis de datos, visualización y reportes automatizados

  • Crear endpoints RESTful con Express/FastAPI

🧪 Protocolos de Pruebas

Pirámide de Testing

/\ / \ / E2E \ → Playwright (10%) /______\ / \ / Integration\ → Supertest/pytest (20%) /______________\ / \ / Unit Tests \ → Jest/pytest (70%) /____________________\

Cobertura Mínima Requerida

Tipo Cobertura Mínima Herramienta
Unitarios 80%+ Jest / pytest
Integración 70%+ Supertest / requests
E2E Flujos críticos Playwright

Workflow de Testing

Commit → Lint → Unit Tests → Integration Tests → Build ↓ Coverage >= 80%? ↓ Yes → Deploy Staging No → Reject

Comandos Estándar

# Unit tests npm run test npm run test:coverage # Integration tests npm run test:integration # E2E tests npm run test:e2e # All tests npm run test:all

Estrategias de Deploy

Estrategia Uso Descripción
Rolling Producción Actualización gradual de instancias
Blue-Green Crítico Dos ambientes idénticos, switch instantáneo

Rollback Automático

  • Trigger: Error rate > 5% en 5 minutos
  • Acción: Revert al último deploy exitoso
  • Notificación: Slack/Email al equipo

⚖️ Reglas de Escalamiento

Los agentes trabajan de forma autónoma (✅) por defecto, pero deben escalar a asistido (⚠️) bajo ciertas condiciones.

🔴 Escalamiento Automático (Obligatorio)

Condición Ejemplo Acción
Seguridad Auth, JWT, OAuth Revisión humana obligatoria
Datos sensibles Queries a producción Aprobación del Arquitecto
Cambios breaking API version changes Review + testing extra
Producción Deploy a prod Arquitecto debe aprobar
Costos Servicios cloud nuevos Evaluación de impacto

🟡 Escalamiento Recomendado

Condición Ejemplo Acción
Complejidad alta +500 líneas, +5 archivos Sugerir revisión
Performance crítico Queries complejos Benchmark requerido
Tecnología nueva Librerías no usadas Documentar decisiones
UX crítico Login, checkout QA manual recomendado

🟢 Permanece Autónomo

Condición Ejemplo Proceso
CRUD estándar Endpoints GET/POST Tests → merge
Componentes UI Botones, cards Linting + tests → merge
Bug fixes menores Typos, estilos Auto-merge si tests OK
Documentación READMEs Merge directo

Matriz de Decisión

1. ¿Datos de usuarios o seguridad?
SÍ → 🔴 ESCALAR | NO → Continuar
2. ¿Afecta producción directamente?
SÍ → 🔴 ESCALAR | NO → Continuar
3. ¿+500 líneas o +5 archivos?
SÍ → 🟡 RECOMENDAR revisión | NO → Continuar
4. ¿Tecnología no probada?
SÍ → 🟡 DOCUMENTAR | NO → Continuar
5. ¿CRUD/UI estándar?
SÍ → ✅ AUTÓNOMO | NO → 🟡 EVALUAR
